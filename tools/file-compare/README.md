# 파일 비교

폴더를 다른 컴퓨터로 옮긴 뒤 빠진 파일, 추가된 파일, 내용이 바뀐 파일을 찾는 오프라인 도구입니다. 영상·이미지·AE·Blender 프로젝트 파일도 같은 방식으로 검사합니다. 디자인의 완성도나 프로젝트의 외부 링크는 검사하지 않습니다.

## 사용

1. `dist/file-compare.html`을 최신 데스크톱 브라우저에서 엽니다. 설치·로그인·서버가 필요 없습니다.
2. **기준**에서 원본 폴더를 고릅니다. **기준 목록 저장**으로 JSON을 저장합니다.
3. 다른 기기에서 같은 HTML을 열고, **목록 불러오기**로 그 JSON을 고릅니다.
4. **받은 폴더**를 고르면 누락·추가·변경이 나옵니다. **결과 저장**으로 검수 결과를 보관합니다.

같은 기기에 원본과 사본이 있으면 두 폴더를 바로 골라도 됩니다. 파일은 브라우저 페이지에서 1 MiB씩 순서대로 읽고, 버퍼를 Worker에 전달해 해시를 계산합니다. Worker가 처리한 뒤 다음 조각을 읽으므로 메모리 사용은 파일 크기에 비례해 늘지 않습니다. Worker·해시 계산·스타일까지 HTML에 들어 있고, CSP로 외부 연결을 막습니다. 페이지를 닫으면 선택과 결과가 사라집니다.

개인 자료와 그 파일명이 담긴 목록은 개인 기기에만 보관하세요. 공유 실습실 Mac/PC에는 이 도구의 공개 코드와 공개·합성 파일만 옮깁니다.

## 판정 범위

- 상대 경로와 파일 크기, SHA-256을 비교합니다. 파일명 대소문자나 NFC/NFD 차이는 별도로 표시합니다.
- 빈 폴더, 시각·권한, 심볼릭 링크/정션 여부, AE·Blender 링크, 미디어 품질은 검사하지 않습니다. 링크 검사가 필요하면 기존 Python `delivery_manifest.py`를 사용합니다.
- 복사·동기화·편집이 끝난 뒤 선택하세요. 브라우저의 파일 선택은 원자적 스냅샷이 아닙니다. 모든 동시 변경을 감지한다고 보장할 수 없습니다.
- 빈 목록은 비교 완료로 처리하지 않습니다. 0바이트 파일도 원래 File을 실제로 읽어 접근 오류를 검사합니다. 일치 후보에 0바이트 파일이 있으면 원본에서도 비어 있음을 확인하기 전에는 일치 판정과 결과 저장을 보류합니다. 일부 Linux 자동화 환경에서 파일명이 잘못 전달되어 0바이트로 읽힌 사례를 피하기 위한 확인입니다.
- 파일 200,000개, 목록 JSON 32 MiB, 합계 `Number.MAX_SAFE_INTEGER` 바이트까지. 파일 목록과 검색은 메모리에 보관하고 표는 50개씩 표시합니다. 보이지 않는 방향 제어·무시 문자는 화면에서 U+번호로 보여 주고 원래 경로는 JSON에 보존합니다. 파일 내용은 전체를 메모리에 올리지 않습니다.
- JSON은 UTF-8 또는 BOM이 있는 UTF-16을 받습니다. 경로의 고립 서로게이트·4,096자 초과 이름은 거부합니다.

## 기존 CLI와 호환

내보낸 목록·결과는 `skills/asset-delivery/scripts/delivery_manifest.py`의 schema 1입니다. 보고서도 받은 폴더의 목록이므로 CLI에서 기준으로 다시 쓸 수 있습니다.

```bash
python3 skills/asset-delivery/scripts/delivery_manifest.py received --compare reference-manifest.json
```

브라우저는 절대 경로를 알 수 없어 `target`에 폴더명만 넣습니다. 정수·인코딩·경로 길이 제한은 Python보다 엄격합니다. 경로 충돌 검사는 Unicode 16 공식 전체 case folding 데이터로 Python의 `NFC(path).casefold()`를 따르며, 일치 비교에는 원래 경로를 그대로 사용합니다.

## 개발

Node 22.20 이상과 Python 3.11 이상을 권장합니다. Python은 호환성 검사에만 필요합니다. 사용자 HTML 실행에는 필요 없습니다.

```bash
npm ci --ignore-scripts
npm test
npm run build
```

`hash-wasm` 4.12.0과 esbuild 0.28.2를 lockfile로 고정했습니다. Unicode 원본의 SHA-256은 `6f1f9c588eb4a5c718d9e8f93b782685e5c7fec872cf05e8e6878053599e09bb`입니다. 제3자 라이선스는 `THIRD-PARTY-NOTICES.txt`와 HTML에 들어 있습니다. 빌드에는 네트워크가 필요하지 않습니다(`npm ci`는 별도).

설계 초안: `../../docs/cloud-20261023-shared-delivery-design.md`. 구현에서는 상하문자 변환 근사법 대신 공식 case folding을, 가상 스크롤 대신 50개 단위 페이지를, 8 MiB 대신 1 MiB 청크를 사용합니다. 검증 결과와 실제 브라우저 범위는 `VALIDATION.md`에 기록합니다.
